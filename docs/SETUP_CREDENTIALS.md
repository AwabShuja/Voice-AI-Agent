# Credentials and ngrok setup

Edit the `.env` file in the project root locally. Do not paste its contents into
chat or commit it. The API and webhook secrets are generated by `scripts/init_local.py`;
keep the existing values when continuing this workspace.

## Values to fill in

| Variable | Where the value comes from |
| --- | --- |
| `API_KEY` | Already generated locally. Use this value in Swagger's patient API authorization and share it privately with reviewers. |
| `VAPI_WEBHOOK_SECRET` | Already generated locally. Copy this into the Vapi bearer credential described below. |
| `VAPI_API_KEY` | Your **private** key from the Vapi dashboard's API Keys page. |
| `GROQ_API_KEY` | Create a key in [Groq Console](https://console.groq.com/keys); also add it to the Groq integration inside Vapi. |
| `NGROK_AUTHTOKEN` | Copy **Your Authtoken** from the [ngrok dashboard](https://dashboard.ngrok.com/get-started/your-authtoken). This is an agent authtoken, not an ngrok API key. |
| `NGROK_DOMAIN` | Copy your account's assigned free domain from the ngrok dashboard's Domains page. Enter the hostname only. |
| `PUBLIC_BASE_URL` | `https://` followed by exactly the same ngrok hostname, without a path. |
| `VAPI_CREDENTIAL_ID` | The ID of the custom bearer credential you create in Vapi below. This is an ID, not the secret itself. |

Leave `VAPI_ASSISTANT_ID` and `VAPI_PHONE_NUMBER_ID` empty for initial provisioning.
If you already have an assistant/number to reuse, enter their existing IDs instead.
Keep `GROQ_MODEL=openai/gpt-oss-120b` and the database settings unchanged.
The selected Vapi-managed Deepgram speech configuration does not require a separate
Deepgram key in this application's `.env`.

## Configure Vapi authentication

1. In Vapi **Integrations**, configure Groq using your Groq API key.
2. Open **Integrations > Server Configuration > Add Custom Credential**.
3. Choose **Bearer Token** and a descriptive name such as `Patient Registration Webhook`.
4. Set **Token** to your local `VAPI_WEBHOOK_SECRET`. Keep **Header Name** as
   `Authorization` and **Include Bearer Prefix** enabled. Enter the secret without
   manually adding `Bearer ` to it.
5. Save the credential and put its ID in `.env` as `VAPI_CREDENTIAL_ID`.

The assistant generator attaches this credential to the assistant and registration
tools. This follows [Vapi's server authentication flow](https://docs.vapi.ai/server-url/server-authentication).

## Start ngrok on Windows

ngrok is already installed in this workspace's current Windows environment.
For another computer, install it using [ngrok's download page](https://ngrok.com/download).

1. Sign into ngrok and copy the authtoken and assigned free hostname into `.env`.
   Set the public origin too. The following hostname is only an example; use the
   exact domain assigned to your own account:

   ```dotenv
   NGROK_AUTHTOKEN=YOUR_PRIVATE_AUTHTOKEN
   NGROK_DOMAIN=your-assigned-name.ngrok-free.app
   PUBLIC_BASE_URL=https://your-assigned-name.ngrok-free.app
   ```

2. Open PowerShell in the project folder and verify the local backend:

   ```powershell
   uv run python -m scripts.check_api
   ```

   If it cannot connect, start the backend in its own terminal:

   ```powershell
   uv run alembic upgrade head
   uv run uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8000 --workers 1
   ```

   If port 8000 is already in use, check `http://127.0.0.1:8000/health` first;
   do not start a second backend on the same port.

3. In another PowerShell terminal, start the tunnel:

   ```powershell
   uv run python -m scripts.start_tunnel
   ```

   The script reads `.env` and forwards the assigned HTTPS address to local port 8000.
   Keep the terminal open and the computer awake while testing. Ctrl+C stops it.

4. Open `https://YOUR_ASSIGNED_DOMAIN/health`, replacing the hostname. Expect:

   ```json
   {"data": {"status": "ok"}, "error": null}
   ```

   Also verify public access and authentication from another terminal:

   ```powershell
   uv run python -m scripts.check_api --base-url https://YOUR_ASSIGNED_DOMAIN
   ```

The free plan provides an assigned development domain and HTTPS. A browser may
show a **Visit Site** notice; ordinary programmatic API requests are unaffected.
The check script includes the documented bypass header. See
[ngrok's free-plan documentation](https://ngrok.com/docs/pricing-limits/free-plan-limits).

If ngrok cannot reach the upstream application, check local `/health` and port 8000.
If ngrok reports that the domain is already online, stop its previous tunnel before
starting this one. Keep `PUBLIC_BASE_URL` and `NGROK_DOMAIN` consistent.

## Provision and test the voice assistant

Confirm your available Vapi credits and leave auto-reload disabled. Then run:

```powershell
uv run python -m scripts.preflight --online
uv run python -m scripts.configure_vapi
```

The first command checks credentials and model availability. The second generates
`.local/vapi-assistant.json` for inspection without creating provider resources.
When those checks pass, apply the configuration and request a free U.S. number:

```powershell
uv run python -m scripts.configure_vapi --apply
```

Use Vapi's browser assistant test first, then a real inbound call. Follow the
[manual acceptance scenarios](ACCEPTANCE.md). A free number is subject to provider
inventory and account eligibility; the script does not buy a paid number.

## Inputs still needed for deployment and submission

- AWS account access through your own console or local profile, verified credit
  balance/expiry, and the intended review window. The application needs no AWS key.
- An EC2 SSH key and reachable instance address after provisioning.
- Your private GitHub repository destination and authenticated Git access.
- The reviewer usernames/emails supplied by the assignment, for repository access.

Follow [the AWS runbook](../deploy/AWS.md) when moving the app and tunnel to EC2.
Stop the laptop tunnel before starting the same domain on EC2. The final review
setup must stay reachable independently of this development computer.
